## SLIDE 2 — Proposed Solution

### The problem, restated

Investigators face one vendor operating five handles across five marketplaces. Today, linking
them is manual, unrepeatable, and produces a number no court will accept. The two hard
questions are **who is this really** and **where do they operate from** — and both answers
must be defensible months later.

### What PRAHARI does — the two halves

**Half 1 · ATTRIBUTION — *who***
Collects the mistakes operators leak *themselves* into public indexes — a reused PGP key, a
shared wallet, a certificate that names a clearnet host, a writing habit, a posting rhythm —
and decides which personas are one actor, with a calibrated confidence and a full evidence
trail.

**Half 2 · SANGAM — *where*** (संगम, "confluence")
Takes that actor and places its footprints on a world map, with **genuine** host → DNS →
geo-IP resolution where a host resolves, and a clearly-labelled *derived* coordinate where it
does not. The map never lets an assumption look like a measurement.

### How it addresses the problem

| Investigator asks | PRAHARI answers |
|---|---|
| Are these five handles one person? | An actor object with personas merged, and a confidence band |
| How sure are you? | **0.84**, calibrated — with a published **3.1% false-merge rate** at α = 0.05 |
| Prove it | The evidence trail recomputes the score exactly, to 12 decimal places |
| Where do they operate? | SANGAM: resolved pins, derived pins, and an explicit "cannot place, here's why" list |
| Will this stand up in court? | Signed hash chain + Merkle inclusion proof, admissible under **BSA 2023 §63** |
| What did you *not* check? | Every gap is written down — see slide 18 |

### Innovation and uniqueness — the three claims

**1 · A confidence score that survives cross-examination.**
Naive tools stack correlated signals and report **0.999** — false certainty. PRAHARI converts
each signal to a likelihood ratio, **collapses signals by root cause** so one fact cannot be
counted five times, then **dampens each by its measured reliability**. Same evidence,
honest answer: **0.84**. That 0.84-vs-0.999 gap is the entire pitch.

**2 · A record nobody can quietly edit.**
Canonical JSON → keccak-256 → hash chain → Ed25519 signature → per-case Merkle root anchored
on Polygon Amoy at **zero gas**. Only 32-byte hashes go on chain — never PII.

**3 · An honest map, and an honest network demo.**
SANGAM draws derived coordinates as hollow dashed pins at 1-decimal precision with **no
random jitter, ever**. And the Tor demo runs a **real** hidden service and a **real** client
that we own, correlating timing at both ends — the actual principle behind onion
de-anonymisation, done legally.

> **Speaker note:** the differentiator is not "we have more signals". It is **"we are the only
> one who will tell you when we're not sure, and show our arithmetic."**

### Methodology

1. **Collect passively.** Only third-party indexes that already hold the data. Certificate
   Transparency is published by CAs; Shodan InternetDB is a scan someone else already ran.
   *Reading an index is not probing a target.*
2. **Extract** entities with regex + gazetteer + spaCy. Hinglish is a first-class input.
3. **Score four ways in parallel** — infrastructure, identity graph, stylometry/behaviour,
   chain flow — each emitting signals tagged with **why** they agree.
4. **Fuse** with likelihood ratios, root-cause collapse and reliability dampening.
5. **Calibrate** with isotonic regression, then publish a **split-conformal** threshold τ so
   the false-merge rate at `p ≥ τ` is bounded by a chosen risk budget α.
6. **Place** the actor's infrastructure on the SANGAM map, class-labelled.
7. **Seal** every analyst action into a signed, chained, on-chain-anchored ledger.

### The trust boundary — worth one line on the slide

The browser **never** talks to the engine. Every call goes through a server-side proxy with a
strict allowlist. `ENGINE_URL` is deliberately not `NEXT_PUBLIC_`, and a pinned test fails the
build if a third reader of that variable ever appears.

### Risks and how each is handled

| Risk | Reality | Mitigation actually in the code |
|---|---|---|
| "You're claiming to break Tor" | We are not, and never claim to | Every source is a public index. `assert_not_onion()` guards every outbound URL, enforced by a **network-layer test**. Measured outbound `.onion` requests: **0** |
| Stylometry is imitable | True — it is the weakest signal | Weighted at **r = 0.5**, half a signing key. A **decoy** persona with a verbatim copied bio is injected into the testbed specifically to prove we catch mimicry |
| Correlated evidence inflates scores | The core failure of naive tools | Root-cause collapse: only the strongest signal per root survives |
| A wallet may be an exchange or mixer | Shared by thousands — not evidence of control | The **financial root is dropped entirely**, not downweighted |
| Free tier sleeps | 15-min spin-down, ~60 s cold start | Two-attempt proxy (45 s, then 60 s retry, GET only) + a budgeted keep-alive. UI says **"waking"**, never "offline" |
| Ground truth is synthetic | The public archive we ingest has no reliable timestamps | **Stated openly.** 244 personas / 3,340 labelled pairs, fixed seed `20260920`, byte-identical digest across runs |
| A source goes down | crt.sh was measured **down**, 0/5 attempts, HTTP 502 | Demoted to failover; certspotter promoted to primary. Every source's freshness is reported |
| Court challenge | The whole design target | Merkle inclusion proof discloses **one** record without the rest of the case — BSA 2023 §63 |

### Degradation contract — nothing hard-fails

Every dependency has an honest fallback and the UI always says which path ran.
Missing Groq key → local regex extractor, badged `local`. Tor won't bootstrap → controlled
replay over the **same real correlation engine**, badged `simulated`. No network → Anvil chain
with a **LOCAL CHAIN** badge. **A badge that misreports which engine ran is a Critical finding.**

## SLIDE 7 — The money slide: the confidence model

**Put this table on screen and walk it left to right. This is the slide that wins.**

Inputs: `s = [0.78, 0.71, 0.83, 0.69, 0.74]`, `r = [0.9, 0.7, 0.8, 0.5, 0.5]`

| Root | Signal | s | LR = s/(1−s) | r | LR^r |
|---|---|---|---|---|---|
| `identity_key` | PGP fingerprint | 0.78 | 3.5455 | 0.9 | **3.1240** |
| `financial` | shared wallet | 0.71 | 2.4483 | 0.7 | **1.8716** |
| `infra` | cert reuse | 0.83 | 4.8824 | 0.8 | **3.5555** |
| `linguistic` | writing style | 0.69 | 2.2258 | 0.5 | **1.4919** |
| `temporal` | posting rhythm | 0.74 | 2.8462 | 0.5 | **1.6871** |

```
LR_total       = 3.1240 × 1.8716 × 3.5555 × 1.4919 × 1.6871 = 52.3219
posterior odds = 0.1 × 52.3219                              =  5.2322
p              = 5.2322 / 6.2322                            =  0.839543
```

| | |
|---|---|
| **PRAHARI** | **0.84** |
| **Naive noisy-OR** `1 − Π(1−sᵢ)` | **0.999** |
| **Gap** | **0.1596** |

**The three steps, in the words to use:**
1. **Likelihood ratios** — a probability is not evidence strength; the ratio is.
2. **Root-cause collapse** — group signals by *why* they agree; only the strongest per root
   survives. *Two views of one certificate are one fact.*
3. **Reliability dampening** — `LR^r`. A PGP key (0.9) is not a writing style (0.5).

Prior odds are **1:10** for a pair that survived blocking, **1:10,000** otherwise — because
being proposed as a candidate is itself weak evidence, and pretending otherwise smuggles in
the base rate.

> **If a judge asks "why not just multiply?"** — because the same certificate can produce four
> signals. Multiply them and you have counted one fact four times. That is exactly how you get
> to 0.999 and exactly why it is wrong.

Fixed seed 42 · 3,340 pairs · 2,004 train / 1,336 validation.

| Metric | Value |
|---|---|

| Recall @ τ(α=0.05) | 0.8833 |
| F1 @ τ(α=0.05) | **0.9381** |
| **False-merge rate @ τ** | **0.031348 ≤ α = 0.05** ✔ |
| Brier score | **0.005333** |
| **ECE (10 bins)** | **0.005083** — "0.84" really means 84% |
| Accepted links @ τ | 93 |

**The conformal guarantee holds at every risk budget:**

| α | τ | measured FMR | holds | accepted links |
|---|---|---|---|---|
| 0.01 | 1.000000 | 0.0000 | yes | 52 |
| 0.02 | 1.000000 | 0.0000 | yes | 52 |

## SLIDE 11 — SANGAM · संगम — the *where*

**"Attribution tells you who. SANGAM tells you where. The confluence of the two is a case
you can actually act on."**

### What it does

Pick an actor, and every footprint it has — markets, infrastructure hosts, wallet off-ramps —
plots on a world map. Real geolocation where a host genuinely resolves; a clearly-labelled
derived coordinate where it does not; and an explicit "cannot place, here is why" list for
everything else.

### The resolution chain — shown to the analyst, step by step, timestamped

```
host → .onion guard → DNS A/AAAA → answers → geo-IP → coordinate
                ↓                                ↓
         reverse DNS                        ASN + org
```

| Property | Value |
|---|---|
| `.onion` guard | **Runs before any lookup.** An onion is UNAVAILABLE by construction (INV-1) |
| Disk cache TTL | **6 hours** — a 512 MB free instance never re-resolves in a loop, and a demo never rate-limits mid-presentation |
| Cache age | **Returned, never hidden** |
| Freshness window | **24 h** — older points render muted with an age chip. *A stale location presented as current is a false statement* |
| Batch cap | 32 hosts |
| Keys required | **None.** Free and keyless (INV-12) |

### Endpoints

`/geo/host` · `POST /geo/hosts` · `/geo/asn` · `/geo/actor/{id}/footprint` ·
`/geo/certificate-links` · `/geo/sources`

### Exports

Class-preserving **GeoJSON** and **CSV** — a derived point stays labelled derived after export.

## SLIDE 12 — SANGAM: the three coordinate classes

**This is the slide that shows judges we thought about honesty at the pixel level.**

| Class | Marker | Meaning |
|---|---|---|
| **RESOLVED** | Solid pin | host → DNS → geo-IP returned a real location |
| **DERIVED** | **Hollow pin, dashed ring** | No resolution. A stable coordinate standing for a known hosting or exchange region. **NOT a measured location** |
| **UNAVAILABLE** | **Not plotted at all** | Nothing to place. Listed with the reason |

> *"A derived point drawn like a measured one is a picture of an assumption presented as
> evidence, and an analyst who cannot tell them apart cannot use either."*

### Four hard rules, each with a test

1. **Derived coordinates round to ONE decimal place** (~11 km). Six decimals would imply metre
   precision the rule does not have.
2. **No random jitter, ever.** Two hosts that genuinely share a location get two identical
   coordinates and are clustered by the UI. Scattering them to look prettier is fabrication.
3. **Deterministic.** The same host yields the same point across runs and across processes, so
   two analysts comparing screenshots see the same map.
4. **`.onion` is never resolved.** UNAVAILABLE by construction, and the reason says so as a
   feature, not an error.

### Shape, not colour

The distinction is carried by **shape first** — colour is skin-dependent and fails for
colour-blind readers. The UI also **refuses to compare** points of different classes, and never
re-derives a class of its own: the engine decides the class, the UI only draws it. A UI that
classified independently could disagree with the payload, and then the map and the API would
be telling an analyst different things.

### Two real bugs this design caught

- **FINDING-06.** `lib/geoderive.ts` emitted a Binance off-ramp marker for **every** actor,
  stamped `inferred: false` and captioned as known fact — a fabricated cash-out claim rendered
  like a measurement. Found by an hour-old test suite, pinned as a failing test until fixed.
- **FINDING-09 (Critical).** `routers/geo.py` handed **any** host to `socket.gethostbyname()`,
  including a `.onion`. Proven with a spy *before* fixing: the query really was issued. The
  pre-existing spy test patched a different function and never covered the geo router. Five
  spies now do, including one against the original code path.

## SLIDE 13 — The audit chain

**The claim is narrow and testable: nobody changed the record after the fact, and we can prove
which analyst made each decision.**

| Layer | Mechanism | Attacker it defeats |
|---|---|---|
| Canonical JSON | Sorted keys, no whitespace, UTF-8, no NaN | Two systems serialising differently — a hash over ambiguous bytes proves nothing |
| Hash chain | `hash_n = keccak(prev_hash ‖ leaf_n)` | Editing record *k* breaks every hash from *k* on, and verification reports the **failing index** |
| Ed25519 | Each record signed by the analyst | Full database write access still cannot forge a signature |
| Merkle root | Per-case tree, anchored on chain | Backdating — a root anchors exactly once |

**Threat model, attacked adversarially:** an attacker with *full database write access* but
without the analyst's private key or the anchorer wallet must not be able to alter, delete,
reorder or replay a record undetected.

**Why the inclusion proof matters:** an analyst hands a court **one** record plus a short
proof. The court verifies that record was in the sealed case **without ever seeing the other
records**, which may concern unrelated suspects. That is the practical reading of BSA 2023 §63.

An odd node is **promoted, never duplicated** — duplicating is the CVE-2012-2459 shape where
two distinct leaf sets produce the same root.

## SLIDE 14 — The on-chain anchor

## SLIDE 15 — Live Tor timing correlation

**"Tor hides which IP you are. It does not hide when you send."**

An adversary observing timing near the client and near the service can line up the two streams
and show they are the same conversation — without decrypting anything. That is the technique
that actually unmasks hidden services.

| Step | What runs |
|---|---|
| 1 | A local HTTP backend that timestamps every request — the *service* observation point |
| 2 | A tor process via `stem` with an **ephemeral** hidden service mapping onion:80 → that backend |
| 3 | A client fetching the `.onion` through tor's SOCKS proxy on a deliberate timing pattern — the *client* observation point |
| 4 | Delay-invariant interval correlation. Returns a confidence and the peak lag (= circuit RTT) |

**Runtime ~30–40 s. Both endpoints are ours**, so observing and correlating them is legal and
reproducible — a genuine network-layer result, not a mock.

If tor cannot bootstrap, it falls back to a **controlled replay over the same real correlation
engine**, badged `simulated`. The maths is identical; only the transport differs.

## SLIDE 16 — Chain flow

Money is the one identifier that has to touch the real world eventually.

- **Common-input clustering** — if one transaction spends from several addresses at once, one
  entity controls all of them; they had to sign for every input. Union-find merges them. This
  heuristic underpins essentially every real chain-analysis tool.
- **Change-address heuristic** — applied conservatively, only when unambiguous, because a wrong
  merge here is a wrong attribution.

A path to a tagged off-ramp is the real-world lead. **A path through a mixer is the
money-laundering signal the PS names — and it also drops the financial evidence**, because a
mixer output is shared by thousands. Real `mempool.space` data, no API key.

## SLIDE 18 — The honesty ledger

**Put this slide in. Judges reward a team that names its own limits before they do.**

### What we deliberately do NOT do

- We do **not** break Tor, and never claim to.
- We do **not** scrape live marketplaces or probe target hosts. Passivity is enforced by a
  network-layer test, not a promise. **Measured outbound `.onion` requests: 0.**
- Behavioural analysis runs on **labelled synthetic ground truth**, because the public archive
  we ingest carries no reliable timestamps.
- **Stylometry is the weakest signal** and is weighted accordingly, deliberately.

### What is declared but not built

| Area | Status |
|---|---|
| Command Panel user CRUD | Read-only. Invite / disable / reset-TOTP have no handlers, so last-admin protection is **not** implemented — and its tests are **absent rather than vacuously passing** |
| Persona merge / split | Not built; ledger actions reserved |
| SANGAM layers | **4 of 10.** Cert reuse, persona overlay, ASN clustering and jurisdiction render toggles but draw nothing; temporal scrubber, movement trails and density heat map are absent |
| `/geo/asn` | Returns null ASN — Cymru's interface is DNS TXT and `dnspython` is not a dependency. The ASN shown comes from `ipwho.is` |
| UNAVAILABLE class | Not reachable from any actor's footprint — **no actor in this dataset carries a `.onion`**. Demonstrated through the host-lookup box instead |
| Solidity tests | 12 exist; `forge` not installed in this environment |
| On-chain anchor | Needs one free faucet claim |

### An honest recall number, explained rather than hidden

Splink recall is **0.8176** against a 0.90 target — and **the ceiling is structural**. Of 159
true pairs, only **130 share any hard identifier**, and Splink finds **130 of 130**
(recall 1.000 on reachable pairs, precision 1.000, **zero** false positives over 3,180
unrelated pairs). The 29 unreachable pairs share no PGP, no wallet and no email — they are
exactly what stylometry, behaviour and fusion exist to catch. *Raising the generator's
identifier-sharing rate would push this past 0.9 while making the task strictly easier.*
